# 0.2.5 — 2026-06-04

## Added

- **`eia_query_route` output**: `total` (total matching rows in the EIA dataset) and `returned_count` (rows in this response) are now required fields in the structured output — consumers no longer need to infer count from `data.length` ([#20](https://github.com/cyanheads/eia-energy-mcp-server/issues/20)).
- **`notice` field** on `eia_query_route` output: optional string present when zero rows matched, containing filter-adjustment guidance. Rendered as a blockquote in `format()` output.

## Fixed

- **`eia_query_route` zero-row behavior** ([#20](https://github.com/cyanheads/eia-energy-mcp-server/issues/20)): valid filters that match no data now return `{ data: [], total: 0, returned_count: 0, notice: "..." }` instead of throwing a `-32001 NotFound` error. Agents can distinguish a valid-but-empty result from a transport error and self-correct via the `notice` guidance without triggering a retry loop.
- **`no_data` error contract** narrowed: the `no_data` reason now only covers the inverted-date-range pre-flight path (start after end), which is genuinely invalid input.
- **Service-layer `no_data` throw** ([#22](https://github.com/cyanheads/eia-energy-mcp-server/issues/22)): the `notFound()` call in `eia-service.ts` (null `resp?.response` path) now includes `recovery.hint`, consistent with the handler-level path.
