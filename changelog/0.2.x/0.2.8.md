# 0.2.8 — 2026-06-20

## Changed

- **`@cyanheads/mcp-ts-core` `^0.10.6` → `^0.10.9`** — picks up the `DuckdbProvider.describe({ tableName })` binder fix (filtered canvas describes raised an ambiguous-column error, [#235](https://github.com/cyanheads/mcp-ts-core/issues/235)) and the canvas SQL gate now classifying `SELECT`-shaped prepare failures (mistyped column, unknown function) as `invalid_sql` with the DuckDB binder detail, instead of the misleading `non_select_statement` ([#236](https://github.com/cyanheads/mcp-ts-core/issues/236)) — both reachable through `eia_dataframe_describe` / `eia_dataframe_query`. Also adds the `ctx.content` collector for image/audio content blocks ([#239](https://github.com/cyanheads/mcp-ts-core/issues/239)) and corrects `OTEL_SERVICE_NAME` seeding precedence in the framework docs.
- **`check-dependency-specifiers` devcheck step** — new `scripts/check-dependency-specifiers.ts` (framework-shipped), hard-fails on floating specifiers (`latest`, `*`, pre-release dist-tags) in `package.json`'s dependency sections and `bun.lock`'s `workspaces` map, catching a `bun update --latest` writing a literal `latest` into the lock that re-resolves the dep past an intentional version hold ([#246](https://github.com/cyanheads/mcp-ts-core/issues/246)).
- **Plugin-manifest validation** — `devcheck.config.json` gains `packaging.pluginManifests: true`, enabling `lint:packaging` check 10 over `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json` (non-empty descriptions, unscoped display names, full-name install args) ([#240](https://github.com/cyanheads/mcp-ts-core/issues/240)). The empty `.codex-plugin/plugin.json` `interface.longDescription` is now filled.
- **Skill re-sync** — 14 framework skills (`add-tool`, `api-auth`, `api-canvas`, `api-config`, `api-context`, `api-errors`, `api-services`, `api-telemetry`, `field-test`, `git-wrapup`, `orchestrations`, `polish-docs-meta`, `report-issue-local`, `tool-defs-analysis`) and 6 scripts re-synced to the framework versions.
