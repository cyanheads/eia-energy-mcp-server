# 0.3.0 — 2026-07-31

## Changed

- **`eia_query_route` canvas spillover now stages the full accumulated result set, not just the previewed page.** `EiaApiService.query()` walks `offset` pages forward from the preview — each bounded by EIA's 5,000-row-per-request ceiling — and registers the accumulated rows under a new `EIA_CANVAS_MAX_ROWS` cap (default 25,000: five requests, ~4 MB of upstream JSON, ~8.5 s worst case). The inline preview stays at the caller's `length`. `canvas_preview_note` now reports the real staged row count and, when the cap binds or a follow-up page fails, the offset to resume from. Accumulation is best-effort — a page that fails after retries keeps the rows already gathered rather than discarding a preview the caller has in hand. (#26)
- **`eia_query_route` error reasons reconciled to what the tool actually throws.** Category routes now throw `route_not_queryable` (`ValidationError`), matching `eia_describe_route`'s existing reason for the same condition — `route_not_found` (`NotFound`) is reserved for routes that genuinely don't exist. The EIA 400 remap is split by the upstream message into `invalid_facet` / `invalid_column` / `invalid_frequency`, each pointing recovery at the right `eia_describe_route` output field; an unmatched message falls back to `invalid_facet`. A 200 response with no `response` envelope now bubbles as a bare `ServiceUnavailable` instead of borrowing the unrelated `no_data` reason. (#35)
- **`eia_search_routes` weak-match threshold recalibrated from 0.5 to 0.9.** The `fuse.js` `^7.5.0` bump normalizes key weights before they become score exponents, shifting every `eia_search_routes` score upward on the same ranking order — the old threshold was labeling perfect matches weak. The threshold is now an exported `WEAK_MATCH_SCORE` constant with a calibration test guarding it.
- **`@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.0`, plus a broader tooling refresh.** `bunfig.toml` gains a Socket scanner (`@socketsecurity/bun-security-scanner`) and a 3-day `minimumReleaseAge` supply-chain guard, with `@cyanheads/mcp-ts-core` excluded for same-day framework adoption; the Dockerfile adds BuildKit cache mounts for `bun install` and installs with `--ignore-scripts`; `docs/tree.md`, the agent protocol, and the project's skills re-synced to the framework's current templates.

## Removed

- **`eia_query_route` `canvas_id` input and output removed.** Every dataset a tenant stages already lands in one shared per-tenant canvas and cross-joins by its `df_<id>` table name — the input parameter never routed anything (`CanvasBridge.acquireSharedCanvas` ignores any scoping argument), and the output field duplicated `dataset`. `dataset` is now the only documented join handle; a caller passing `canvas_id` has it silently stripped rather than echoed. (#28)
- **`eia_query_route`'s `length_exceeded` error contract entry removed**, along with the unreachable service-side guard behind it — the input schema's `.max(5000)` already owns the bound, so no code path could ever produce the reason. (#35)

## Fixed

- **`eia_query_route` paging past the end of a result set no longer suggests enabling DataCanvas when it's already enabled.** The spillover branch was gated on row count rather than bridge presence, so an `offset` beyond `total` fell through to the canvas-disabled message. It now returns a notice naming the offset and total (e.g. "Offset 9,999 is past the last row — total is 25. Reduce offset below total…"), and `appliedOffset`/`appliedLength` are echoed in enrichment so the empty page is self-diagnosing. (#32)
- **EIA's top-level `warnings[]` never reached `eia_query_route`.** The service read `response.warnings`, which EIA always leaves `null` — the API actually returns `warnings` as a sibling of `response`. `DataResponse.warnings` is retyped from `string[]` to `EiaWarning[]` (`{ warning, description }`), and `truncation_warning` now populates EIA's "incomplete return … paginate with offset" guidance instead of staying empty. (#27)
