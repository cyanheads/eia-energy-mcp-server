# 0.3.1 — 2026-07-31

## Added

- **`eia_describe_route` caps facet values per facet at `EIA_FACET_VALUE_CAP` (default 50).** Each facet in the response carries `value_count` and `values_truncated`; new `facet` and `values_offset` inputs page one facet past the cap. `structuredContent` and `content[]` compute independent truncation hints from their own offsets — `format()` still previews 5 values and names the next call from its own preview length. The per-route metadata cache is unaffected: it keeps the full, uncapped value set, which is what offset paging and the search index below read from. A new `facet_not_found` error (`NotFound`) covers an unknown facet ID, with the route's facet IDs in the error data. (#29)
- **`eia_search_routes` indexes facet values.** A bounded background pass at warm time fetches the fuel-type, sector, technology, and coal-rank facets named in the route tree (`VOCABULARY_FACET_IDS` in `route-cache.ts`, matched with case/punctuation stripped), 4 requests at a time; every `eia_describe_route` call also folds its route's values in at no extra upstream cost. Both paths skip facets over 200 values. Matching entries carry a `filter_hint` (e.g. `{"fueltypeid": "WND"}`) the same way STEO series results already do — `addSteoSeriesToIndex` is generalized to `addEntriesToIndex`, deduping on route + hint so the two population paths can overlap. (#36)
- `EIA_FACET_VALUE_CAP` env var (default `50`), added to `server-config.ts`, `.env.example`, and both `server.json` npm blocks.

## Fixed

- **`eia_describe_route` no longer throws `TypeError: meta.frequencies.map is not a function` when EIA returns `frequency` as an object map instead of an array.** `fetchAndCacheMetadata()` now normalizes `rawNode.frequency` the same way it already normalizes `data` — an array passes through, an object map flattens via `Object.values()`, anything else degrades to `[]`. `RawRouteNode.frequency` widens to `RawFrequency[] | Record<string, RawFrequency>`. (#31)
