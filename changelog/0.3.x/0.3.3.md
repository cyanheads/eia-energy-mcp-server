# 0.3.3 — 2026-07-31

## Added

- **`eia_search_routes` reports index completeness.** New `indexComplete` output field is `true` only when the answer was ranked against the whole corpus; `indexGaps` (present when `false`) lists route paths whose metadata could not be fetched plus any index-widening pass that didn't land (`steo_series`, `facet_values`). The empty-result `notice` now distinguishes a genuine no-match from a corpus that is still short. (#38)

## Fixed

- **`eia_search_routes` no longer ranks against a half-filled index.** `search()` now awaits both the route tree and the STEO/vocabulary index passes via the new `ensureIndexWarmed()`, bounded by a 45 s `SEARCH_WARM_BUDGET_MS` ceiling so a degraded upstream can't hold a call past a client's own request timeout. Previously the two passes ran fire-and-forget inside the warm, so a search issued during the ~11–24 s window could rank a mediocre hit into the top slot with nothing in the response showing the corpus was incomplete. `eia_browse_routes`, `eia_describe_route`, and `eia_query_route` are unaffected — they wait only on the unchanged `ensureTreeWarmed()`. (#38)
- **`buildRouteTree` no longer silently drops a subtree when a node's metadata fetch fails.** The build is now paced by a `ConcurrencyGate` at `TREE_BUILD_CONCURRENCY` (8) instead of an unbounded ~270-request `Promise.all`, and a node that still fails after its retry budget is marked `incomplete` rather than falling back to its bare stub, which `isLeafNode` used to misclassify as a genuine leaf. A serial second pass re-fetches whatever missed the first burst; anything still incomplete is re-fetched on demand by `repairNode()` the next time `eia_browse_routes` reaches it, instead of being lost for the process lifetime. (#39)
