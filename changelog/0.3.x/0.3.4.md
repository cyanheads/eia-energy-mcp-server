# 0.3.4 — 2026-07-31

## Added

- **`scripts/search-battery.ts` and `scripts/eval-search.ts`** — a labelled on-target/off-target query set and the runner that scores `eia_search_routes`'s `phrase` and `combined` modes against a live-warmed or snapshotted corpus. Run via new `bun run eval:search` (needs `EIA_API_KEY`; ~30s warm).

## Fixed

- **`eia_search_routes` now reaches the route behind a multi-term query.** Fuse matches a query as a single fuzzy contiguous run, so a query combining a commodity, a metric, and a sector (e.g. `electricity price residential`) never made `electricity/retail-sales` a candidate at all — no route's text contains that run, however well it holds the data. `searchRoutes()` in `route-cache.ts` now also scores each query term independently via `tokenizedScores()` and combines them with a weighted geometric mean: term weight is inverse document frequency (function words dropped outright), admission requires clearing both a matched-weight bar and a matched-term-count floor, and a term of `VERBATIM_TERM_LENGTH` (4) characters or fewer must match verbatim rather than fuzzily. Each entry keeps the better of its whole-phrase and per-term score; a single-term query has nothing to tokenize and takes the unchanged phrase path alone, preserving #36's facet-value resolution by construction. (#37)
- **`WEAK_MATCH_SCORE` re-derived: 0.9 → 0.72.** Measured with `scripts/eval-search.ts` against the live 2,103-entry corpus: the labelled battery's answerable queries surface their route at or below 0.6600, its unanswerable queries score at or above 0.7632, and 0.72 sits in that gap. (#37)
