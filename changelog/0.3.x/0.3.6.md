# 0.3.6 — 2026-08-05

## Changed

- **`eia_dataframe_query`** reads the framework's `QueryResult.truncated` and surfaces it as a new `truncated` enrichment field. The notice now distinguishes the two caps: a `row_limit`-bound result states the rows shown and the cap that dropped the rest without counting them, and names both escapes (raise `row_limit`, or `register_as` to materialize the whole result with an exact `COUNT(*)`); a `preview`-narrowed result keeps its `Showing N of M rows` form. ([#40](https://github.com/cyanheads/eia-energy-mcp-server/issues/40))
- **`eia_describe_route`** renders the same facet-value window on `content[]` and `structuredContent` — `FORMAT_PREVIEW_VALUES` (5) is gone, `EIA_FACET_VALUE_CAP` is the only bound on either surface, and both name the same next `values_offset`. ([#43](https://github.com/cyanheads/eia-energy-mcp-server/issues/43))
- **`eia_describe_route`**'s `format()` drops a facet value's `alias` from the rendered `id=name (alias)` line when the alias only restates the pair — EIA's generated `(id) name` form, or `name` alone — and keeps it when it prefixes a class the pair doesn't name (`Region: (MAT) Middle Atlantic`). The `alias` output field itself is unchanged on both surfaces. ([#46](https://github.com/cyanheads/eia-energy-mcp-server/issues/46))

## Fixed

- **`eia_describe_route`** — a `values_offset` past a facet's last value no longer returns an empty window shaped like a complete one. The response now carries a `notice` (new `enrichment.notice` field) naming every facet the offset emptied, its `value_count`, and its last valid offset. ([#42](https://github.com/cyanheads/eia-energy-mcp-server/issues/42))
