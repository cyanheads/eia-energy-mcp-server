# 0.3.8 — 2026-08-05

## Fixed

- **`eia_query_route`**'s `format()` now decides each `{col}-units` companion from the whole preview instead of row 0: a unit constant across every row still folds into the header, a unit absent from every row is dropped, and anything else — varying by row, or null on some rows only — stays as its own body column. Previously a column whose unit followed a facet value (`electricity/electric-power-operational-data`, `electricity/facility-fuel`) could have every row mislabeled with row 0's unit, or lose the whole units column to a null on row 0. ([#49](https://github.com/cyanheads/eia-energy-mcp-server/issues/49))
- **`eia_query_route`** now maps EIA's `Invalid sort '…'` and `Invalid date format '…'` 400 bodies to new `invalid_sort` and `invalid_period` reasons, each with a recovery hint naming the field actually rejected. Both previously fell through to `invalid_facet`, whose hint pointed at `facets[].id` regardless of what was wrong. ([#51](https://github.com/cyanheads/eia-energy-mcp-server/issues/51))
- **`eia_query_route`** no longer forwards EIA's `incomplete return` advisory on the canvas-absent path once `canvas_preview_note` has already placed the inline page against `total` — the advisory's fixed "5000 rows" text duplicated a gap the note already accounted for. ([#54](https://github.com/cyanheads/eia-energy-mcp-server/issues/54))
