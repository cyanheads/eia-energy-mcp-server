# 0.4.0 — 2026-08-05

## Added

- **`eia_query_route`** gains a `stage: boolean` input (default `false`). With `stage: true`, the service pages past the inline preview and stages the accumulated rows as a `dataset` (`df_<id>`) DataCanvas table — the same accumulation behavior the tool ran automatically before this release. Left at the default, a call costs one upstream request and stages nothing. ([#50](https://github.com/cyanheads/eia-energy-mcp-server/issues/50))

## Changed

- **Breaking:** `eia_query_route` no longer stages a canvas table automatically whenever a canvas is configured and the match exceeds the preview. Existing callers relying on the implicit `dataset` handle must pass `stage: true` to keep getting one; `canvas_preview_note` on an unstaged call now names `stage: true` as the way to reach the rest. ([#50](https://github.com/cyanheads/eia-energy-mcp-server/issues/50))
- `eia_dataframe_describe`, `eia_dataframe_query`, and `eia_dataframe_drop` are now wrapped in `disabledTool()` at `createApp()` when `CANVAS_PROVIDER_TYPE` is unset, rather than registered unconditionally and failing at call time. A deployment with no `CANVAS_PROVIDER_TYPE` set now advertises 4 tools instead of 6 (or 7 with `EIA_DATAFRAME_DROP_ENABLED=true`); all three remain visible on the HTTP landing page with an enable hint (`CANVAS_PROVIDER_TYPE=duckdb`). `eia_dataframe_drop` gates on canvas presence ahead of its existing `EIA_DATAFRAME_DROP_ENABLED` flag, and its disabled card names whichever gate is actually unmet. Canvas-enabled deployments see no change — same tools, same schemas. ([#52](https://github.com/cyanheads/eia-energy-mcp-server/issues/52))

## Fixed

- **`eia_browse_routes`** now accepts the same route spellings — leading, trailing, and doubled slashes — that `eia_describe_route` and `eia_query_route` already tolerated by falling through to a live EIA fetch that normalized server-side. Route paths are normalized once at the service boundary for all three tools, so the metadata cache holds one entry per route instead of one per spelling, and `eia_describe_route`/`eia_query_route` output echoes the normalized route rather than the caller's input. ([#53](https://github.com/cyanheads/eia-energy-mcp-server/issues/53))
