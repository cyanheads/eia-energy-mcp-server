# 0.4.1 — 2026-08-25

## Added

- **`.env.example`** documents the mcp-ts-core 0.12 env vars: `MCP_HTTP_MAX_BODY_BYTES`, `MCP_HTTP_RESUMABILITY`, `MCP_HTTP_RESUMABILITY_MAX_EVENTS`, `MCP_HTTP_RESUMABILITY_TTL_MS`, `MCP_GC_PRESSURE_INTERVAL_MS`, `MCP_LOG_RATE_LIMIT_THRESHOLD`, `MCP_LOG_RATE_LIMIT_WINDOW_MS`.
- **Dockerfile** gains a `HEALTHCHECK` against `/healthz` and an `ARG APP_VERSION` wired to `org.opencontainers.image.version` — the release build already passes `--build-arg APP_VERSION`, which was previously dropped on the floor.
- **`.github/CONTRIBUTING.md`** and **`.github/CODE_OF_CONDUCT.md`**.

## Changed

- **Breaking:** `@cyanheads/mcp-ts-core` `^0.11.1` → `^0.12.3`. Tool inputs are now strict — an undeclared top-level argument is rejected with an error naming the key, where it used to be silently dropped. Nested objects and `z.record()`-typed fields (e.g. `filters`) are unaffected.
- **Bun** pinned to `1.4.0` across both Dockerfile stages and `packageManager`; `engines.bun` stays `>=1.3.0`.
- **`MCP_SESSION_MODE`** in `.env.example` settled to `stateless`, matching the Dockerfile; the comment now names all three values (`stateless` / `stateful` / `auto`) and the real default (`auto`, which resolves to `stateful`).
- Dockerfile's two `bun install`/`bun add` steps now pass `--omit=peer`, dropping the framework's optional peer tiers (test runner, service SDKs, parsers) from the production image; nothing this server imports at runtime is affected.

## Fixed

- **`EiaApiService.fetchJson`**'s `withRetry` call now passes `context: ctx`, so a retried or rate-limited request logs under its own request correlation instead of unscoped. Covered by tests confirming the EIA API key never appears in a log line, on the happy path or a retried failure.
