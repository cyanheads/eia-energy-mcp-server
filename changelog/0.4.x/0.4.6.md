# 0.4.6 — 2026-10-23

## Added

- **Series IDs**: `eia_search_routes` resolves a legacy APIv1 series ID such as `PET.RWTC.W` through EIA's `/v2/seriesid` lookup to one result carrying its route, `filter_hint`, and new optional `frequency` and `columns`. An unrecognized or failed lookup returns the text search with a notice. ([#79](https://github.com/cyanheads/eia-energy-mcp-server/issues/79))
- **Benchmark search**: the warm-time index covers the `series` and `product` values of the daily and weekly petroleum and natural-gas routes and the `respondent` values of the hourly and daily RTO routes, so `Henry Hub`, `WTI crude spot price`, `Cushing`, and `Electric Reliability Council of Texas` resolve before any describe. ([#78](https://github.com/cyanheads/eia-energy-mcp-server/issues/78))
- **Facet value lookup**: `eia_describe_route` takes `values_query`, a case-insensitive substring match over each value's `id`, `name`, and `alias`. Per-facet `values_matched` counts the matches, and `values_offset` pages them. ([#80](https://github.com/cyanheads/eia-energy-mcp-server/issues/80))

## Changed

- **Search ties** order by route path and filter instead of index position, so results no longer depend on the order the warm's fetches landed in.

## Fixed

- **Inverted ranges**: `eia_query_route` compared `start` and `end` as strings, rejecting valid mixed-granularity ranges (`2023-01` to `2023`) and passing inverted ones (`2023-10` to `2023-Q3`). It now checks only when EIA returns no rows, comparing the periods each bound selects at the response frequency, and `no_data` names both. ([#88](https://github.com/cyanheads/eia-energy-mcp-server/issues/88))
- **Local-hourly bounds** without a UTC offset (`2024-02-01T02`, `2024-02-01`) are refused as `invalid_period` before the request; EIA answered them with HTTP 500, which was retried as an outage. ([#89](https://github.com/cyanheads/eia-energy-mcp-server/issues/89))
- **Impossible periods** (hour 24, `2024-02-30`) at daily, weekly, hourly, and local-hourly frequencies are refused as `invalid_period` the same way. ([#93](https://github.com/cyanheads/eia-energy-mcp-server/issues/93))
- **EIA timeouts**: requests had no per-request timeout. Each attempt now ends at 45 s and a call's attempts share a 56 s deadline, after which the four route tools fail with retryable `upstream_timeout`. A stalled warm fetch lands in `indexGaps`, and staging that runs out of time keeps the rows already staged. ([#90](https://github.com/cyanheads/eia-energy-mcp-server/issues/90))
- **Route repair**: a failed re-fetch of a route the warm left incomplete reported every cause as `upstream_invalid_response`. It now carries the underlying `rate_limited`, `upstream_unreachable`, `upstream_unavailable`, or `upstream_timeout`; a 404 is `route_not_found`. ([#92](https://github.com/cyanheads/eia-energy-mcp-server/issues/92))
- **Claude Desktop bundle** excludes tests, sources, scripts, docs, and editor and CI config. ([#94](https://github.com/cyanheads/eia-energy-mcp-server/issues/94))

## Security

- **Search query bound**: `eia_search_routes` searches at most the first 256 characters of a query, which bounds the work one search can do. `effectiveQuery` echoes the searched text, and a notice says when the query was cut.

## Dependencies

- Bun `1.4.3 → 1.4.4` (Docker images, `packageManager`).
