# 0.5.1 — 2026-11-03

## Added

- **`eia_search_routes` indexes data-column aliases** in the new `SearchIndexEntry.terms` key, so "nameplate capacity" reaches `electricity/operating-generator-capacity` and "gross generation" reaches `electricity/facility-fuel`. ([#97](https://github.com/cyanheads/eia-energy-mcp-server/issues/97))
- **Monthly Energy Review series are searchable**: the 984 `total-energy` `msn` series are indexed by name and by ID (`TETCBUS`), with `filter_hint: {"msn": ...}`, through a new `total_energy_series` index pass that `indexGaps` names when it did not land. ([#103](https://github.com/cyanheads/eia-energy-mcp-server/issues/103))
- **Balancing authorities answer to ISO/RTO acronyms** in `eia_search_routes` and in `eia_describe_route` `values_query`: `ERCOT` finds `ERCO`, `CAISO` finds `CISO` and `CA`, `NYISO`, `SPP` (`SWPP`, `SWPW`), `ISO-NE`, `MISO`, and `PJM` likewise. The table applies only to the balancing-authority facets (`respondent`, `fromba`, `toba`, `parent`, `balancing_authority_code`) of `electricity/` routes. ([#102](https://github.com/cyanheads/eia-energy-mcp-server/issues/102))

## Changed

- **`eia_describe_route` points a unitless column at its unit.** For a named column with no unit in the route metadata, the notice names its `{column}-units` row field where a row carries one and says a column whose rows carry none has no unit (descriptor columns such as `county` and `latitude` on `electricity/operating-generator-capacity`); for the `value` column of a `{ value: [] }` route it names `units` or `unit`. ([#98](https://github.com/cyanheads/eia-energy-mcp-server/issues/98))
- **`eia_describe_route` reads a column unit written under a singular `unit` key**, as `densified-biomass/inventories-by-region` does (`tons`). ([#98](https://github.com/cyanheads/eia-energy-mcp-server/issues/98))
- **`canvas_preview_note` names the inline page's row range** (`rows 21–30 of 55`) and says when it is the last page instead of suggesting more paging. Past offset 0, its `stage: true` advice names offset 0, since a stage starts at `offset`; with the canvas off, it says staging is unavailable on this deployment. ([#104](https://github.com/cyanheads/eia-energy-mcp-server/issues/104))
- **Tool descriptions, recovery hints, and runtime notes no longer name server env vars.** The dataframe tools' `canvas_unavailable` recovery, the `eia_dataframe_drop` description, `eia_query_route`'s `stage` and `canvas_preview_note` descriptions and runtime notes, and `eia_describe_route`'s facet `values` description say what the caller can do, not which setting the operator changes.

## Fixed

- **`eia_query_route` refuses an impossible period bound with `invalid_period` before any request.** v0.5.0 returned rows for another period or retried EIA's HTTP 500 as an outage. Now refused: ([#101](https://github.com/cyanheads/eia-energy-mcp-server/issues/101))
  - a month outside 01–12, at any frequency;
  - an hour that is not two digits, at any frequency;
  - a day its month lacks, or an hour 24–99, at daily, hourly, and local-hourly;
  - a day its month lacks, at weekly and four-week-average (EIA answers four-week-average with HTTP 500); an hour 24–99 there still goes to EIA, since whether its rollover reaches another week depends on the route's weekly calendar;
  - at monthly, quarterly, and annual, only a day or hour that rolls the bound out of the period it names (`2024-02-30` at quarterly still goes through).
- **`international` `productId`, `activityId`, and `unit` no longer draw a false "not in the complete cached vocabulary" notice.** EIA publishes those lists partial; `eia_describe_route` names them in its notice, and on any route a filter value that a returned row carries under that facet is never reported unmatched. ([#100](https://github.com/cyanheads/eia-energy-mcp-server/issues/100))
- **A facet response that returns 200 without its value list** is a retryable `upstream_invalid_response`, not an empty list: the index pass lands in `indexGaps` and `eia_describe_route` lists the facet in `unavailable_facets`. ([#103](https://github.com/cyanheads/eia-energy-mcp-server/issues/103))
