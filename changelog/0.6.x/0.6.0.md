# 0.6.0 — 2026-11-14

## Added

- **`eia_search_routes` finds a STEO or SEDS series by its bare ID** (`PATCPUSX`, `MGTCB`): both vocabularies' IDs are search terms, as Monthly Energy Review `msn` IDs already were, and an ID two vocabularies share (`NGMPPUS`) returns both entries first. ([#107](https://github.com/cyanheads/eia-energy-mcp-server/issues/107))
- **`eia_dataframe_query` answers `SHOW <table>`**, and `range()` and `generate_series()` with constant arguments.

## Changed

- **Breaking: `eia_dataframe_query` refuses a system-catalog name used as an alias, a CTE name, or a `register_as` name**: a DuckDB internal metadata view name (`pg_class`, `pg_tables`, `duckdb_tables`, …) as a column alias or CTE name, and that or `information_schema` / `pg_catalog` as a `register_as` name, fail as `system_catalog_access`. 0.5.1 answered these; pick another name — a longer one that only contains a catalog name (`pg_tables_2024`) works.
- **Breaking: `eia_browse_routes`, `eia_describe_route`, and `eia_query_route` refuse an EIA endpoint path as `route_not_found` before any request**: a `data` or `facet` segment, or a leading `seriesid`, as the request URL resolves the path. On 0.5.1, `eia_query_route` with `columns` on `{route}/data` returned the route's rows; it now fails `route_not_found` with a hint to resend the route before `/data`. ([#108](https://github.com/cyanheads/eia-energy-mcp-server/issues/108))
- **A route path is read as the request URL reads it before it is checked, cached, or echoed**: `\` is `/`, `.` and `..` segments resolve, the path ends at `?` or `#`, and blank segments drop, so `petroleum\pri\spt` and `petroleum/x/../pri/./spt` resolve and echo as `petroleum/pri/spt`, and a path whose `..` climbs above the API root fails `route_not_found` before any request. ([#108](https://github.com/cyanheads/eia-energy-mcp-server/issues/108))
- **A gate refusal's recovery is the framework's hint followed by the tool's declared recovery**, so the engine-derived fix (a syntax error's, a PIVOT's IN list) reaches the caller beside the EIA tool names.
- **Calls the SQL gate already refused now report another reason**: `"pragma_table_info"(…)` is `denied_function`, `COPY … TO` is `non_select_statement`, `SHOW` or `DESCRIBE` of a missing table is `missing_table`, and `system.main.duckdb_tables` is `system_catalog_access`.
- **A non-SELECT statement's refusal no longer names its statement type**: the message is `Canvas query must be SELECT.` and `data.statementType` is `UNKNOWN`, where 0.5.1 answered a `CREATE TABLE … AS` with `got CREATE.` and `CREATE`. A quoted file path fails with the gate's `names a file, not a staged table` message.
- **`engines.bun` rises to `>=1.4.4`** (README prerequisite updated). Framework scripts, skills, `changelog/template.md`, and `.env.example` (`MCP_JWT_EXPECTED_AUDIENCE`, `MCP_JWT_EXPECTED_ISSUER`) are re-synced to `@cyanheads/mcp-ts-core` 0.13.22.

## Fixed

- **Concurrent first stagings share one canvas per tenant** instead of each minting one and orphaning the others' dataframes, through `DataCanvas.acquireShared`. Provenance is read before the canvas is described, so a table committing mid-listing keeps its provenance. ([#109](https://github.com/cyanheads/eia-energy-mcp-server/issues/109))
- **`eia_query_route` discloses a weekly or four-week-average bound whose hour 24–99 EIA reads past a period date**: the notice names EIA's reading and the date-only bound that selects the named day. The bound is sent as written, never refused. ([#106](https://github.com/cyanheads/eia-energy-mcp-server/issues/106))

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.13.18 → ^0.13.22`: the canvas SQL gate refuses DuckDB internal metadata views by name, and `DataCanvas.acquireShared` backs the shared canvas.
- `@biomejs/biome` `2.6.4 → 2.6.7` (dev).
